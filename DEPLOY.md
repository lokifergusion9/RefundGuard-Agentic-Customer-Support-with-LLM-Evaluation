# Deploy on Render + Neon (free)

The live demo runs as **one Render web service** (free, 512 MB) and **two Neon databases** (free, pgvector included). Nothing here is needed for local development: see the Quickstart in the README.

## What runs where

| Piece | Where | Notes |
|---|---|---|
| Agent API, `/demo`, `/review`, `/docs` | Render, one process (`deploy/server.py`) | `RUN_EXECUTION=inline`: no separate worker |
| Mock payments, shipping, ticketing | Same process, under `/mock/payments`, `/mock/shipping`, `/mock/ticketing` | Still called over HTTP with their API keys; state is in memory |
| Evaluation API and screens (`/eval`, `/ui/experiments`) | Same process | Reads `EVAL_DATABASE_URL` |
| `support` database (application) | Neon | Business tables are re-seeded on every start |
| `support_eval` database (experiments) | Neon | Restored from your local database, so the real experiments show up |

Measured locally: about 300 MB with the embedding model loaded, under the 512 MB limit.

## 1. Neon: two databases

1. Create a free project at [neon.com](https://neon.com) and, in it, two databases: `support` and `support_eval`.
2. Copy the **direct** connection string (not the pooled `-pooler` one: LangGraph's checkpointer holds a connection). Change the scheme so SQLAlchemy uses psycopg 3:

   ```text
   postgresql+psycopg://USER:PASSWORD@HOST/support?sslmode=require
   postgresql+psycopg://USER:PASSWORD@HOST/support_eval?sslmode=require
   ```

3. Copy your local experiments into `support_eval` (about 17 MB). With the local stack up (`docker compose up -d postgres`), use the Postgres client inside that container. Use the plain `postgresql://` form of the Neon URL here:

   ```bash
   docker exec customer-support-resolution-agent-postgres-1 \
     pg_dump -U support -d support_eval --no-owner --no-privileges -Fc -f /tmp/support_eval.dump
   docker exec customer-support-resolution-agent-postgres-1 \
     pg_restore --no-owner --no-privileges -d "postgresql://USER:PASSWORD@HOST/support_eval?sslmode=require" /tmp/support_eval.dump
   ```

   Skip this step and the eval screens start empty (the migrations still run).

## 2. Render: the web service

1. Push the repository to GitHub. In Render: **New â†’ Blueprint**, pick the repository; `render.yaml` defines the service.
2. Fill in the values marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon `support` URL above |
   | `EVAL_DATABASE_URL` | the Neon `support_eval` URL above |
   | `LLM_API_KEY` | a free [Google AI Studio](https://aistudio.google.com/) key, with no billing linked |

   `JWT_SECRET` and the three mock API keys are generated by Render. Never use the `.env.example` defaults on a public host.
3. Deploy. On each start `deploy/start.sh` migrates both databases, loads the policies, starts the server, then seeds the demo data into the database and the mocks.

## 3. Use it

Pages carry no data: they call the API with a token you paste in. Mint tokens on your machine, signed with the same secret:

1. Copy `JWT_SECRET` from the Render dashboard (Environment) into your local `.env`.
2. Mint and paste:

   ```bash
   uv run python -m scripts.mint_token "auth|alice" --minutes 240                          # /demo
   uv run python -m scripts.mint_token "auth|reviewer_riya" --role reviewer --minutes 240  # /review
   uv run python -m scripts.mint_token "auth|operator" --role operator --minutes 240    # /ui/experiments
   ```

   Put your local secret back afterwards if you also run the stack locally.

## Limits to know

- **Sleeps after 15 minutes idle.** The next visit waits about a minute while it starts, migrates and re-seeds. Open it a few minutes before a demo.
- **Every start resets the demo data** (business tables and mocks). Experiments in `support_eval` are kept.
- **Gemini free-tier quota.** Anyone with a token can spend it. Hand out short-lived tokens only; experiments are better run locally.
- **Neon sleeps after 5 minutes idle**, so the first query after a pause is slower.
- Free-tier terms change: check Render's and Neon's pricing pages if something stops working.
